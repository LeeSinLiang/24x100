# 24×100: final report

Built Sat 26 – Sun 27 Sep 2026 for the AI for Housing Hackathon (Track 1). This report covers what is real,
what is partial, what was cut, the gates, the judge panel before and after, how each claim was verified, and
what a person on the team still has to do. Decisions and their reasons are in `docs/decisions.md` (1–51).

## What was built

- **A one-screen workspace** (spec §0.15). Map · Plan · Graph · Table sit in the centre. An inspector on the right
  gives a status, one plain sentence and four numbers, then the tabs Money · Rules · Site · Next · Sources. A
  tray at the bottom holds what to check next, the evidence timeline and changes. It is light by default, with a
  dark cyanotype toggle, and nothing scrolls at 1440×900.
- **The engine**: one result object per scenario.
  - Edge-aware envelopes from the City's parcel polygons, with deed arithmetic first.
  - Refusals when the records disagree, when lots don't touch, when districts are mixed, or when a lot is
    unknown.
  - An unlock search over fixed levers. Use permission drives what it suggests.
  - Money screened first, with no score.
  - Site unknowns, deal-killers first.
  - Letters built only from engine facts, each number checked.
- **Citywide.** 11,247 City-owned vacant lots, classified live. Districts whose rules aren't loaded stay grey.
  The classifier agrees with the lot engine on built neighbours and on §925.06.C.1.
- **The C15 assembly finder** (spec §0.14). Runs of 2–3 lots on one block face that fit as of right when
  combined. It shows owner type only.
- **The graph** (spec §0.15 P1). Every node is a real record: a parcel, a rule and its quote, a signature, a
  dataset, an estimate, a sale, a site check or an office.
- **AI extraction with review.** Gemini through LangChain proposes typed rules with verbatim quotes. Guards drop
  anything unquoted. Rules stay pencil until a named person signs. There is a publish path for reviews (a
  steward uploads the file, and a check runs).
- **Keeping it current.** Refresh with pencil diffs, a static JSON API, and a watchlist digest that is off by
  default and runs as a dry run.

## What a person on the team has to do before submission

1. **Review and approve the site** (preview: `npm run build && npm run preview` → http://localhost:4173/).
2. **Sign the rules as a person.** Open `?view=review&district=RM-M`, check each rule against its highlighted
   quote, and sign with your name and role (about 15 minutes). Publish the signatures with the steward path
   (`docs/pilot.md`).
3. **Re-record the film after approval.** Run `node scripts/demo.mjs --record --base <recording build>`. Sign B07
   as the person who checked it:
   `REVIEWER_NAME="Sin Liang Lee" REVIEWER_ROLE="Student, team 24×100" node scripts/demo.mjs --record --base <recording build> --only B07`.
   Then check that `film/clips/cues.json` has no placeholder note, and regenerate the facts
   (`npx tsx scripts/facts.ts`).
4. **Re-run R1D‑H with the default model** when the free-tier quota allows:
   `uv run python -m extract run --district R1D-H`, then `uv run python -m extract eval`.
5. **Remove the dev fixture from history before publishing.** It is a synthetic citywide file labelled "DEV
   FIXTURE (not real)", added in `728b386` and removed in `75f529e`. This rewrites history, so do it only before
   the first push:
   ```bash
   git filter-branch --index-filter 'git rm -r --cached --ignore-unmatch web/src/components/city/__dev__' -- --all
   ```
6. **Publish.** No remote exists yet.
   ```bash
   gh repo create <owner>/24x100 --public --source . --remote origin
   git push -u origin master
   ```
   Then enable GitHub Pages (Actions) if you want the publish-reviews workflow. The nightly refresh workflow is
   `workflow_dispatch` only until someone turns it on.
7. **Check the `.env`.** The `.env` holds API keys and is gitignored. Confirm with `git status` before the first
   push that it isn't listed.
